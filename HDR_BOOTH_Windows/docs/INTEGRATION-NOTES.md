# Production integration notes

## Camera
The supplied APK includes native libraries for libgphoto2 and UVC. That proves the Android package carries those camera stacks, not that the same binaries work on Windows. Build a Windows x64 camera adapter with a supported Canon EDSDK release or a Windows-compatible libgphoto2 port. Validate each EOS model, firmware, USB mode, live-view support and SDK licensing. Keep the camera SDK on a dedicated worker thread and marshal decoded preview frames to the UI.

## Printer
Use installed Windows Epson drivers and Windows print APIs. Test every target printer, paper size, borderless mode, orientation, color management and duplicate-copy behavior. Do not assume all Epson models expose identical settings.

## Payments
DOKU secrets must stay server-side. The Windows app should request a payment intent from a backend, display the payment instructions/QR, and unlock capture only after a verified server callback/status check. Wedding/free mode is an explicit event policy, not a payment bypass.

## QR and cloud
QR should contain an opaque, expiring gallery URL generated by the backend. Upload queue must persist locally (SQLite), retry with backoff, and expose pending/uploading/synced/failed states. Manual upload must work after network restoration.

## Data
Use SQLite migrations and store originals locally under Pictures/HDR BOOTH. Keep session IDs, capture metadata, frame IDs, print jobs, payment references and sync states. Back up the database before schema migration.
